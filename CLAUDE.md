# Hibi (日々) — guide for Claude

Hibi is Noa's English study site for his private students and Noa's English Club members, live at
https://learnwithnoa.github.io/cheatsheet/ (GitHub Pages from this repo, `main` branch, public repo).
Noa (he/him, spelled "Noa") is an English coach in Chile. He isn't a developer: explain things in plain words, never ask him to run commands.

## Files

- `index.html` — the whole app (one big page). **Generated. Never edit it by hand**: the next build overwrites it.
- `build/` — the recipe that generates `index.html` (see below). Edit here.
- Hand-written, edit directly: `hub.html`, `hubview.js`, `members.html`, `private-students.html`, `teacher.html`, `coaching.html`,
  `buddy.js` (study buddy pet; bump its `?v=` cache number where index loads it), `comfort.*`, `tbar.js`, `sw.js`, `fb.js`, `emb.js`, `ios-sound.js`.
- `music.js`, `version.json` — generated by the build.
- `tools/hubsync.py` — Noa's helper for reading/changing Hibi's data (students, classes, club). See "Data" below.
- `pod/` — podcast MP3s; `.github/workflows/podcast-audio.yml` converts episodes queued in `pod/queue.txt`.

## Build

```
bash build/build.sh          # builds index.html, music.js, version.json at the repo root
```
How the recipe works:
- `build/build_site.py` starts from `build/english-pack.html`, then runs the change steps `build/parts/step14.py` … `step119.py`
  (chained: each `stepN.py` ends by exec-ing the next; the chain is listed at the end of `parts/step19.py`), adds `cloud.js`.
- Each step edits the page text `s` with `R(old, new)` — `old` must match **exactly once** or the build stops.
  CSS goes before `</style>`. JS is appended with: `_j=s.rfind('</body>'); s=(s[:_j]+_js+s[_j:]) if _j>=0 else (s+_js)`.
- After that, `parts/ext/*.patch` are applied and `parts/post_*.py` run on the finished `index.html` (the live board and
  the What's new list live there; edit those files for changes to them). Inside Python strings in post scripts write CSS newlines as `\\n`.
- **To make a change:** add a new step file (`parts/step120.py`, then 121, …) and append `exec(open("parts/step120.py").read())`
  to the end of `parts/step19.py`. Don't rewrite old steps unless a fix needs it.

## Test

```
(curl -s -o /dev/null localhost:8768 || (python3 build/test/srv.py >/dev/null 2>&1 &))
node build/test/smoke.js     # desktop + phone, reports page errors, screenshots in /tmp
```
`build/test/fbstub3.js` fakes the sign-in so tests never touch real data. Copy `smoke.js` to test a specific change
(click through it, check the DOM, look at the screenshots on desktop **and** iPhone 13 size). Close the What's new pop-up first.

## Deploy

```
git add -A && git commit -m "<what changed, plain words>" && git pull --rebase && git push
```
If `version.json` conflicts in the rebase: take either side, `git add version.json`, `GIT_EDITOR=true git rebase --continue`.
Pages updates about a minute after the push. End commit messages with the attribution lines your session asks for.

## Every change, every time

- Update **What's new** (the `CHANGELOG` list, added in `build/parts/post_118.py`; newest first, short, plain English, member-facing)
  and anything else on the site that describes the feature — especially the **"How this page works"** tour. Noa asks for this every time.
- Check the design on a phone: spacing, text size, nothing cut off, works in light and dark mode.
- Spanish on Hibi may use ¿ and ¡ (Noa's other Spanish copy never does).

## Data (tools/hubsync.py)

- Needs Noa's helper password as the env var `HUB_PASSWORD` **only** (e.g. `export HUB_PASSWORD='…'` in the same command).
  It is not in this repo. Ask Noa for it if a change needs Hibi's data. Never print it or write it into any file, commit, doc, email or reply.
- Run `python3 tools/hubsync.py` with no arguments to list its commands (students, classes, recaps, club posts, recordings, backups…).
- Rules: students must never see private notes (the "About" text, boleta, emails, health, money, family). "View as" must never change anything.
  Lesson plans are never shown to members before class. Ask Noa before adding uncertain payments or deleting data. Never invent data.
